## 目标、适用范围与基本原则

### 目标
在「用 AI 提升效率」与「防敏感信息外泄」之间取得可控平衡，使敏感数据在离开本地前已被妥善处理，且全过程可追溯、可审计、可复核。

### 适用范围
- **通用前置（新增）**：执行任何「任务输入可能接触敏感信息」的任务之前——输入含文本 / 文件 / 数据库 / 知识库 / 代码等任一形态——均先跑「输入检测闸门」（见 §0）：检出敏感则本地脱敏后再执行任务，未检出则直接执行。
- 任何将本地文本 / 文件 / 数据库 / 代码**送至云端大模型**处理的场景（上云专项，见 §3 六步 + SKILL.md 动作一/二）。
- 覆盖：个人私密资料、财务/审计底稿、投资投研材料、客户/员工个人信息、代码中的密钥与 Token。
- **不适用（豁免脱敏）**：**仅本地处理、判定无需外发**的信息（数据不出本机；或仅从云端获取「处理方法」、数据仍留本地处理）——**不脱敏**，但须满足三条护栏（合理访问权限、无外泄风险、不得与外发脱敏副本一起存放）；**豁免以「不外发」为前提——本地处理中追加/生成的数据如需外发，须重新检验脱敏（外发即失效；多次外发每次检测+记录）**，详见 §0.6。

### 基本原则（优先级从高到低）
1. **本地存储优先**：原始敏感文件始终留在本地，绝不整份上传。
2. **最小必要**：只上传完成任务所必需的最小字段；只授权本地读取，逐份标记、逐份脱敏，不得批量读取/上传。
3. **分类分级**：先识别、标记、定级，再选脱敏方法。
4. **可溯源 / 留审计**：记录「哪些数据经云端处理、用了什么方法、映射表在哪、结果如何复核」。
5. **云端记忆禁存敏感信息**：云端对话记忆、知识库、长期记忆均不得写入可识别的敏感原文。

**信任边界**：本地 Agent 框架可信，云端 LLM 不可信；所有敏感原文只进本地，出本地前必须脱敏。

## 背景与原思路修订

原思路已给出正确主干（本地存储、分级、脱敏后上云、映射记录、审计留痕、云端记忆禁存），但存在概念混淆与缺漏。本次主要修订：

| 序号 | 原思路的问题 / 缺漏 | 本次修订 |
|---|---|---|
| 1 | "脱敏后上云前做可逆性检测"，但未界定脱敏法律属性，易误以为"脱敏后就可自由上传" | 明确：本地映射表实现的"可逆脱敏"本质属于**去标识化**，去标识化后**在法律上仍是个人信息**；映射表/密钥本身等于原始数据，必须**与脱敏副本分离存储、加密、最小权限管控** |
| 2 | 三级风险（低/中/高）过粗，无判定依据 | 对接 GB/T 37964、JR/T 0197、GB/T 45574，给出可操作判定表，并补充**准标识符聚合重识别风险** |
| 3 | "投研不去脱敏数值"方向对，但表述模糊 | 提炼为"**去标识、不扭曲数值**"：仅剥离个人标识，**保留精确数值**（持仓、金额、比率），避免泛化/随机化毁掉精度；并补充证券场景拦截"内幕信息/未公开重大信息" |
| 4 | 未说明脱敏对 AI 任务精度的影响 | 新增精度影响章节，给出"方法—精度损失—可逆性"对照表 |
| 5 | 缺工具落地、映射表安全、定期重评估、泄露应急、人员责任 | 新增工具选型、映射表安全条款、应急与改进；引入 GB/T 37964「监控审查」与 GB/T 42460「重标识风险分级」 |
| 6 | "兼容多 Agent 框架"未界定信任边界 | 明确：**本地 Agent 框架可信，云端 LLM 不可信**；敏感原文只进本地，出本地前必须脱敏 |
| 7 | 自动化工具能否兜底未提及 | 明确：自动化识别**不能保证 100% 召回**（尤其中文弱），脱敏后必须**人工复核**，禁止"一键脱敏即上云" |

## §0 输入检测闸门（任务执行前的通用前置）

本 SOP 不仅管"上云前"，也作为**所有任务执行前的通用前置**：只要任务输入可能含敏感信息（文本/文件/数据库/知识库/代码），就在执行任务前先检测、按需脱敏，再执行；无敏感则直接执行（零额外负担）。

**闸门决策表**（与 `desensitize.py guide` 及 SKILL.md「一张图看懂流程」一致；单一来源为脚本内置 `GUIDE_TEXT`）：

| 判定条件 | 动作 | 护栏 / 留痕 |
|---|---|---|
| 仅本地处理 · 无需外发 | 不脱敏 | 三条护栏；外发即失效 + 多次外发每次检测 |
| 显式声明公开 / 已脱敏 | 不脱敏 | 可上云；留痕 + 警示（绝不静默） |
| 检出敏感 | run 脱敏 | preprocess → run → 自查 → 上云 → 审计 |
| 未检出 | 直接执行 | 零额外负担 |

### 0.1 按输入形态的检测方式（均本地离线、数据不出本机）

| 输入形态 | 检测方式 |
|---|---|
| 文本 / 聊天输入 | 落地为临时文件 → `desensitize.py scan`；或 §2 三级表快速判定 |
| 文件（单文件 / 目录） | `desensitize.py scan <路径> --recursive`（覆盖文本/代码/Office/PDF/SQLite；图片/加密/纯图片 PDF 进 skip manifest 并提醒） |
| 数据库 / 程序查询结果 | 本地先导出文本（SQL dump / CSV / `sqlite3 .dump`）再 scan；禁止把查询结果原文外传 |
| 知识库 / 网页抓取 | 抓取内容落地为文本后再 scan；同时遵守"云端记忆/知识库禁存敏感原文"（SKILL.md 清单第 10 项） |

### 0.2 分支决策
- **判定「仅本地处理 · 无需外发」** → **不脱敏**，直接用原始数据在本地执行（省去脱敏工作量）。须满足 §0.6 三条护栏（合理访问权限、无外泄风险、不得与外发脱敏副本一起存放）；**豁免以「不外发」为前提——本地处理中追加/生成的数据如需外发，须重新检验脱敏（外发即失效；多次外发每次检测+记录）**。工具侧 `--local-only` / `--local-paths` 留痕 + 警示。
- **用户显式声明公开 / 样例 / 已脱敏** → 跳过脱敏闸门（见 §0.5「显式声明豁免」）。
- **检出** → 本地 `run --mode hybrid`（建议 `--names 姓名清单`）脱敏，副本入 `desensitized/`、映射表入 `.desensitize_keys/`（分离、加密、密钥 600）；之后**用脱敏副本继续原任务**。任务若需回写实名，于本地 `decrypt` 恢复映射表后回填，映射表永不离开本地。
- **未检出** → 忽略，按任务原流程直接执行，不做任何脱敏。

### 0.3 闸门原则
- 闸门只做"检测 + 按需脱敏"，不阻断正常任务；清洁输入仅付出一次轻量 `scan`。
- 自动化识别非 100%（中文尤弱），脱敏后必须人工复核，禁止"一键脱敏即上云"。

### 0.4 本地预处理关卡（脱敏前必做 · 防割裂 · 自动解密 / OCR）

> 加密文档、图片 / 图片型 PDF、抽取异常等若只在 `run` 末尾散落一句"跳过"，极易被后续流程忽略，造成割裂感与漏脱敏。故把它们**前置为统一关卡**：`preprocess` **直接执行**本地解密与本地 OCR，并把结果汇入**预处理确认单**，供用户确认 / 校对后，再进 `scan`/`run`。

**命令**（默认即自动解密 / OCR，数据全程本地）：
```
desensitize.py preprocess <文件或目录> [--recursive]
    [--passwords-file ./pw.txt] [--out-dir ./preprocessed]
# 仅分类+提醒（旧行为）加 --no-auto
```
`preprocess` 在 `./preprocessed/`（或加 `--workspace <目录>` 时归入统一工作区 `02_未脱敏副本/` 下）产出 `ready/`（解密后 + 原可直接处理文件）、`ocr/`（OCR 文本，未脱敏须校对）、`desensitize_preprocess.json` 与 **`desensitize_preprocess_summary.md`（确认单）**。确认单满足四点（详见 SKILL.md 同名章节）：

**① 原文件与未脱敏副本 · 保存 / 外发情况**：确认单第一节表格列出每个原始文件与其未脱敏副本（解密副本 / OCR 文本 / ready 副本）的**保存位置（本地）与外发状态（🚫 禁止）**，供用户逐条确认绝不上云。
- ⚠️ **严禁外传**：解密密码、加密原文件、已解密未脱敏副本、原始图片 / OCR 文本、映射表——全部留本地。仅在本地完成解密 + 脱敏后，脱敏副本方可上云。

**② OCR 结果 · 需用户逐项校对**：确认单第二节逐条列出 OCR 产出文件（对应原始图片 / PDF），提醒用户**逐字校对**识别文本（重点关注姓名 / 证件号 / 银行卡 / 金额），确认无误后再脱敏。

**③ 预处理异常清单（须另行处理后发回 AI Agent）**：解密失败（密码错误 / 非标加密）、OCR 库缺失、缺抽取库、文件损坏、未知二进制等，确认单第三节**详细列出**（文件 / 类别 / 原因 / 建议），并明确"异常未处理前禁止 run，请用户本地处理后将结果发回 AI Agent 重新纳入"。

**④ 确认与继续（闸门）**：`run` 加 `--preprocess-manifest <确认单JSON>` 后**再次校验：清单仍含异常则拒绝执行**，异常清完才放行——从源头杜绝"跳过异常直接上云"。

**实现要点**：
- **本地 OCR（rapidocr + onnxruntime，v2.4 起）**：纯 pip 安装，**模型（PP-OCRv6 det/cls/rec）随 wheel 捆绑，完全离线、数据不出本机**，无需任何外部服务/端口/守护进程。图片直接识别；图片型 PDF 由 **pypdfium2** 渲染页面后识别。识别前把图像归一化到最长边 ≤2000px、并按尺寸自适应 `Det.limit_side_len`（实测 1000–2100px 为稳定识别区；默认 736 会把整页文字压碎、2500px+ det 不稳定）。已知弱项：**单行极端宽高比图片**（如 1000×120 横幅）识别率低，请改用正常版面或截图分行。
- **本地解密**：加密 PDF 用 **pikepdf**（封装 QPDF，稳健）产出未加密副本；加密 Office 用 **msoffcrypto-tool**。密码来自 `--passwords-file`（每行一个候选；该文件本身含敏感信息，**严禁外传**），缺失时该文件进入③异常清单、由用户本地处理后发回。
- **PDF 文本抽取**：v2.4 起由 pdfminer.six 换成 **pypdfium2**（Chrome 同款 PDFium，C 实现，快且对畸形 PDF 稳健；与 OCR 渲染共用一库）。
- **Python 版本**：标准（非 free-threaded）CPython **≥3.10 且 <3.14**（onnxruntime 无 free-threaded wheel、3.14 支持未完备），`scripts/.python-version` 锁定 3.13。
- **优雅降级**：无密码文件 / OCR 库缺失时，对应项**不静默放过**，而是进入③异常清单等待用户处理，绝不假装已处理。
- **部署注意**：headless Linux 服务器上 opencv-python 需系统库 `libgl1`（`apt-get install -y libgl1`）。

> 红线：脱敏副本可上云；上述一切未脱敏材料严禁外传。预处理后仍须人工复核，禁止"一键脱敏即上云"。

**统一成果中心（工作区，opt-in）**：各阶段命令加 `--workspace <目录>` 后，所有产物归拢到一处并以清晰中文目录命名（`02_未脱敏副本/`🚫、`03_脱敏副本/`✅可上云、`04_映射表_保密/`🚫、`06_审计与回填/`、`07_本地处理不外发/`🚫 等），`run` 额外生成 `05_上云前自检报告.md`（OCR 副本 / 脱敏副本 / 本地不外发 / 公开豁免四处校对 + 确认闸门），并自动维护 `成果索引`；随时 `status --workspace <目录>` 回显。详见 SKILL.md「统一成果中心」节。不带 `--workspace` 时完全保持原默认行为（向后兼容）。

### 0.5 显式声明豁免（无需脱敏的信息，由用户声明；默认全脱敏）

v2.5.0 起**不再自动识别"公开主体"并豁免**——上市公司等也有未公开/内幕信息，自动豁免既难维护又易错漏（把未公开信息当公开放过）；也**不再用文件名/目录名隐式推断**（`sample`/`demo`/`pub` 等常见命名、或"公开"子串会被误判为公开而跳过脱敏）。改为**默认全脱敏，仅当用户显式声明时才跳过**。三种声明形式：

| 形式 | 落地 | 接入点 |
|---|---|---|
| ① 提示词声明 | 用户在提示词写明"公开/样例/已脱敏"→ Agent 跳过闸门；工具 `--assume-public`（整体声明） | §0 分支 + argparse |
| ② 指定文件/文件夹声明（推荐） | 用户指明"文件夹 X 全部 / 其中 a.xlsx 无需脱敏"→ Agent 转 `--public-paths <路径>...`；文件夹=其下全部（递归），文件=该文件 | `is_public_declared` + `_resolve_public_paths` |
| ③ 伴随清单（高级） | 目录内 `.nodesens`/`desensitize_manifest.json`（每行 路径/通配符，`#` 注释），或 `--public-manifest <文件>`；适合"长期公开"的重复使用 | `discover_public_manifests` |

> 数据库/知识库等非文件源由 Agent 在闸门直接记为"已声明公开"，不经本脚本；`--public-paths` 仅作用于文件/文件夹。

**安全补丁（贯穿所有形式，绝不静默跳过）**：
- 被声明豁免的文件一律进入「跳过清单」，在控制台与 `desensitize_report.json` 中明确告警"请确认确为公开信息"，并附带 **size / sha256** 供外发前核对——误声明会导致敏感信息未经脱敏直接外传，故强制留痕 + 二次确认。上市公司未公开信息红线不改（默认全脱）。
- **scan 仍检测**：被声明豁免的文件在扫描时仍检测并报告命中，若发现疑似敏感内容追加"⚠ 你声明为公开，但检出疑似敏感，请复核"提醒（fail-safe 不反转）。
- **会话级一次性**：除高级伴随清单外，声明默认只对本轮对话生效，不落盘为永久设置。

> 用法：`desensitize.py scan/run <路径> --recursive [--assume-public] [--public-paths <路径>...] [--public-manifest 自定义清单]`
> 输出单独分组列出「公开声明豁免」文件（含声明依据 / size / sha256）并附警示；其余文件仍按原规则脱敏。

### 0.6 本地处理·无需外发豁免（不脱敏 · 仅本地处理 · 外发即失效）

**核心动机（减负）**：脱敏的目的是"上云"——不上云就不必脱敏。对**仅本地处理、判定无需外发**的信息，**不做脱敏操作**，直接用原始数据在本地执行，省去脱敏工作量，并避免对财务/审计数值的潜在精度损失。

> ⚠️ **豁免以「不外发」为前提，外发即失效（核心补丁）**：`--local-only`/`--local-paths` 声明的"不脱敏"只对"当前不外发"成立。**本地处理过程中追加或生成的数据**（新增内容 / 派生结果 / 导出文件等）如需外发，豁免**即刻失效**——必须重新走「输入检测闸门」：`scan` 检验是否已脱敏 → 检出敏感则 `run` 脱敏（副本 + 映射表）→ 留痕（映射表支持 `restore` 回填）。**所有外发的数据都必须确保已脱敏并记录以备复核、回填**；绝不把豁免过（未脱敏）的数据或其派生数据直接外发。
> 🔁 **多次外发（每次都要检测 + 记录）**：任务过程中**多次外发**数据的，须在**每次外发时**检测是否已脱敏并记录——已脱敏的**沿用原脱敏记录**（复用原映射表与审计记录，避免重复脱敏、保持令牌一致）；未脱敏的**先补充脱敏记录再外发**（`scan` 检验 → 检出敏感则 `run` 脱敏补充映射表 → 留痕，再外发）。

**判定「无需外发」的两种场景**：
1. **纯本地处理**：全程本地完成，数据不离开本机（本地脚本 / 本地工具 / 本地离线模型等）。
2. **云端取「方法」、本地处理「数据」**：从云端获取**处理方法**（模型 / 脚本 / Skill / 代码 / 算法步骤等）后回到本地处理数据——**「方法」可上云，「数据」绝不上云**。数据仍不外发，同样豁免脱敏。

**三条护栏（强制，缺一不可，否则仍须脱敏）**：
1. **合理访问权限、无外泄风险**：原始文件保持本地最小权限（目录/文件权限收窄、不开启共享、不放入同步盘），确保无外泄风险。
2. **不得与外发的脱敏副本一起存放**：豁免文件绝不放进可上云目录（`desensitized/`、工作区 `03_脱敏副本/`）；工作区模式自动归入 `07_本地处理不外发/`（🚫 不外发），与脱敏副本物理隔离。
3. **留痕 + 可审计**：报告与自检报告明确列出豁免文件（含 size/sha256）并警示"仅本地处理、严禁外发"。

**声明通道**（对称公开豁免，仅本次任务生效）：

| 形式 | 落地 | 接入点 |
|---|---|---|
| ① 提示词声明 | 用户写明"仅本地处理、无需外发"→ Agent 转 `--local-only`（整体声明） | §0 分支 + argparse |
| ② 指定文件/文件夹声明（推荐） | 用户指明"文件夹 X 全部 / 其中 a.xlsx 仅本地处理"→ Agent 转 `--local-paths <路径>...`；文件夹=其下全部（递归），文件=该文件 | `is_local_declared` + `_resolve_public_paths` |

**与「公开声明豁免」的区别（勿混用）**：

| 豁免类型 | 语义 | 是否脱敏 | 能否上云 |
|---|---|---|---|
| 公开声明（`--assume-public` / `--public-paths`） | 内容公开 | 不脱敏 | ✅ 可上云 |
| 本地处理（`--local-only` / `--local-paths`） | 内容保密、只本地处理 | 不脱敏 | 🚫 **严禁上云** |

**安全补丁（fail-safe，绝不静默）**：
- 被声明「仅本地处理」的文件一律进跳过清单并**明确告警"请确认仅本地处理、绝不外发"**（含 size/sha256）。
- **scan 仍检测**：扫描时仍检测并报告命中，若发现疑似敏感内容追加"⚠ 声明仅本地处理但检出疑似敏感，请复核"。
- **本地处理优先于公开**：同一文件同时命中两种声明时，按更严格的「本地处理（不外发）」处理。

**实现要点**：`is_local_declared()` 判定（全局声明 → `--local-paths` 文件/文件夹，复用 `_resolve_public_paths` 做纯路径解析）；新增 `_record_local_only()`（size/sha256 留痕）与 `_copy_to_local_only()`（工作区模式复制到隔离目录）；`process_file` / `_process_extracted` 同步支持 local 分支（local 优先于 pub）；`_report_skipped()` 单独分组「本地处理·无需外发豁免」；工作区新增 `07_本地处理不外发/` 目录 + 自检报告第三节 + `_refresh_index` 条目。

> 用法：`desensitize.py scan/run <路径> --recursive [--local-only] [--local-paths <路径>...] [--workspace <目录>]`
> 工作区模式下豁免文件原样复制到 `07_本地处理不外发/`（隔离、不脱敏），并在 `05_上云前自检报告.md` 第三节留痕；非工作区模式仅留痕、文件留原处。

## §1 关键概念（避免误判）

- **脱敏 / 去标识化 (De-identification)**：通过技术处理，使数据**在不借助额外信息（映射表/密钥）时**无法识别个人。**可逆**（有映射表）。**法律属性：仍是个人信息**，需继续按 PIPL 保护。本 SOP 的本地映射表方案即属于此类。
- **匿名化 (Anonymization)**：处理后**无法识别特定自然人且不能复原**。**不可逆**。法律属性：**不再是个人信息**，可自由使用。
- **关键风险**：去标识化的"可逆钥匙"（映射表 / 密钥）一旦与脱敏副本一起泄露，等于原始数据泄露。因此**映射表必须与脱敏副本分开存储、加密保存、最小权限访问**。
- **直接标识符**：单独即可识别个人（姓名、身份证号、手机号、银行卡号、人脸、住址、邮箱、设备ID等，详见附录 A）。
- **准标识符**：单独不能识别，但**组合**可重识别（性别+出生日期+地区+职业+收入区间等）。即使删了姓名，组合准标识符仍可能"拼回"个人。

## §2 敏感信息分类分级

### 2.1 三级风险判定表（满足任一即归入）

| 级别 | 判定条件 | 上云策略 |
|---|---|---|
| **高风险** | ① 含直接标识符（姓名/身份证/手机号/银行卡/人脸/住址/邮箱等）<br>② 含敏感个人信息（GB/T 45574：生物识别、医疗健康、金融账户、行踪轨迹、特定身份、未成年人信息、宗教信仰）<br>③ 含核心数据/重要数据（JR/T 五级中 4–5 级）<br>④ 含内幕信息/未公开重大信息（证券场景）<br>⑤ 准标识符组合后可重识别（如稀疏群体） | **不直传**。必须本地去标识化（剥离直接标识符+处理高风险准标识符）后方可上云；映射表本地留存 |
| **中风险** | ① 含一般个人信息（非敏感）<br>② 含准标识符（性别、年龄、地区、职业等）单独或弱组合<br>③ 含金融信息 C1/C2 类<br>④ 含具体数值但无个人标识 | 脱敏（去标识化）后可上云；数值类建议保留精度仅去个人标识 |
| **低风险** | ① 通用问答/模板/规则<br>② 已公开的聚合统计<br>③ 无个人指向的脱敏后结构化字段 | 可直接上云 |

### 2.2 准标识符聚合风险
即便删除了姓名和身份证，若保留"女性+1990年生+深圳+某三甲医院+特定病种"，在小样本下仍可能重识别。处理原则：
- 对高唯一性组合做泛化（如具体日期→月份/年份，详细地址→城市）；
- 对极小群体记录做抑制（整条删除）或加噪声；
- 用 GB/T 42460 思路评估重标识风险是否低于可接受阈值（可用 K-匿名：等价类 size ≥ k）。

## §3 脱敏操作流程（六步）

```
本地原始文件
   │
   ├─ ① 数据盘点与识别（标记敏感字段 + 分级）
   ├─ ② 确定脱敏方法与策略（按类型选技术，见 §6）
   ├─ ③ 执行脱敏（本地脚本/工具）→ 生成 工作区/desensitized/（工作区模式为 03_脱敏副本/）副本
   ├─ ④ 验证（重标识风险评估 + 可逆性/完整性检测）
   ├─ ⑤ 审计与溯源（写映射表位置、操作日志）
   └─ ⑥ 仅脱敏副本可上云；原始文件留本地
```

**① 识别标记**：逐份打开本地文件，列出敏感字段及级别，形成"敏感字段清单"。

**② 选方法**：
- 标识符 → 遮蔽/掩码/假名化/令牌化（可逆，本地留映射表）
- 数值（财务/持仓/金额）→ **保留精确值，仅去个人标识**（不泛化、不随机化）
- 文本自由内容 → 仅删除/替换 PII 片段，保留实质性业务内容
- 聚合统计 → 可用泛化/均化

**③ 执行**：用本地脚本或 Presidio 等工具生成脱敏副本，统一放入 `工作区/desensitized/`（工作区模式为 `03_脱敏副本/`）目录，**该目录下的文件才允许发送大模型**。

**④ 验证（关键）**：
- *有效性*：检查脱敏副本不含直接标识符、高风险准标识符组合；必要时按 GB/T 42460 粗略评估重标识风险等级。
- *可逆性*（针对去标识化）：用本地映射表能正确还原 → 证明本地复核可行。
- *完整性*：确认脱敏未误删业务实质内容（避免"为脱敏而毁掉分析"）。

**⑤ 审计**：记录映射表存放路径（加密）、所用方法、操作时间、操作人。

**⑥ 上云**：大模型只接收 `desensitized/` 内容；**原始文件与映射表永不离开本地**。

### 映射表（重识别钥匙）安全条款
- 映射表单独存于 `工作区/.desensitize_keys/`（与 `desensitized/` 物理分离）；
- 映射表**加密存储**（如 AES，密钥不入库）；
- 访问最小权限，操作留痕；任务结束或无需复核后可按计划销毁。

## §4 脱敏对 AI 任务精度的影响

> 核心结论：**脱敏方式决定精度损失。正确做法是"去标识、不扭曲数值"——剥离个人标识，保留业务实质与精确数值。**

### 4.1 各脱敏方法对精度的影响

| 脱敏方法 | 是否可逆 | 精度影响 | 适用场景 | AI 任务风险点 |
|---|---|---|---|---|
| 遮蔽/掩码（138****1234） | 可逆（映射表） | 标识符失效，但**数值/文本语义完整** | 姓名、手机号、账号、身份证 | 几乎不影响分析；仅当任务依赖"真实身份判定"时需本地还原 |
| 假名化/令牌化（张三→P001） | 可逆 | 同实体可关联、可计数、可分组，**关系结构完整** | 需跨记录关联的个人 | 不影响统计分析；失去真实姓名语义（多数任务无需） |
| 抑制/删除字段 | 不可逆 | **丢失该维度** | 非必要字段 | 若删的是实质业务字段，分析不完整 |
| 泛化（20岁→20–30岁；日期→年） | 不可逆 | **降低颗粒度**，区间/趋势类结论可用，精确值丢失 | 聚合统计、公开共享 | 财务/持仓若泛化→金额失真、比率错、异常检测失效 |
| 随机化/均化（数值±扰动） | 不可逆 | **总和/均值/极值改变**，个体不可还原 | 测试数据、开发样本 | 审计勾稽、对账、估值场景**严重失真**，禁止用于精确分析 |
| 文本 PII 替换 | 可逆 | 仅去标识片段，保留其余语义 | 含 PII 的文档 | 若误删实质内容则分析缺料（需控制只删标识符） |

### 4.2 精度影响机制（供用户决定是否提供更准确信息）
- **标识符类脱敏（遮蔽/假名）**：对 AI 的"计算/推理/归纳"精度**基本无损**，因为模型处理的是值而非真人。返回后用本地映射表还原即可。唯一例外：任务本身需要"真实身份"语义（如"此人是否与被审计单位存在关联关系"），此时应在本地侧用真实数据判断。
- **数值类泛化/随机化**：会**实质性改变**财务勾稽关系、持仓比例、估值结果、异常识别。若用户为"安全"而把金额泛化，AI 给出的结论将偏离真实，反而产生误导。**因此财务/审计/投研场景严禁对数值泛化或随机化，只去个人标识。**
- **结论**：当任务依赖精确数值时，用户应提供"已去个人标识但数值精确"的副本；只有当任务仅做宏观聚合统计时，才可使用泛化/随机化。

## §5 场景专项要求

### 5.1 财务 / 审计
- 审计底稿、涉密财务数据**禁止输入公共 AI 平台**（中注协 2025 提示、会计师事务所数据安全管理暂行办法）。
- 确需用 AI 时：在技术环境、数据流转、访问权限**安全受控**前提下，先按本 SOP 脱敏；在底稿中记录 AI 使用过程与结果（审计准则第1131号）。
- 核心/重要数据按 JR/T 五级与暂行办法分类；日志留存（核心≥3年、重要≥1年）。

### 5.2 证券投资 / 投研
- **内幕信息 / 未公开重大信息红线**：证券价格敏感、未公开的信息不得上云，违者涉内幕交易（主动与过失泄露均担责，见《证券法》第53条）。技能须专项拦截。
- 普通投研材料：执行"去标识、不扭曲数值"——剥离个人标识（研究员姓名、客户身份、账户），**保留持仓、金额、比率等精确值**以保障分析精度。
- 投研决策依据完整留痕（指导意见要求保存≥20年）。

### 5.3 代码
- 代码一般不含业务敏感信息，但**账号、密码、API Key、Token、私钥必须脱敏**后方可上云。
- 确需上传含密钥代码时：先检出并替换为占位符，明确告知脱敏方式及影响，**经用户确认**后方可处理。
- 程序代码默认不上云；上云前强制扫描密钥类敏感串。

## §6 工具与技术选型

### 6.1 推荐本地工具栈（数据不出本机）
- **Microsoft Presidio（开源，MIT）**：Analyzer（识别 PII：正则+NLP+校验和+上下文）+ Anonymizer（替换/遮蔽/哈希/加密）。支持文本、图像、结构化数据。可本地 Docker/Python 部署，**数据不出本机**。
  - 局限：中文识别模型较弱、自动化**不能保证 100% 召回** → 必须人工复核。
- **自定义正则 + 本地脚本**：针对中文身份证、手机号、银行卡、内部工号、合同号等写 PatternRecognizer；与 Presidio 组合。
- **映射表加解密**：用 AES 本地加密 `.desensitize_keys/`，密钥不入库。
- **Faker / 数据合成**：用于生成测试样本（不可逆，适合开发/演示）。

### 6.2 脱敏技术五大族（GB/T 与行业实践）
1. **假名化**：替换为虚构标识 / 令牌（可逆，保关系）。
2. **抑制**：屏蔽、掩码、局部/记录抑制（不可逆）。
3. **泛化**：取整、区间、顶层/底层编码（不可逆，降颗粒度）。
4. **扰乱**：重排、均化、范围内随机、浮动（可逆/不可逆，保统计特征）。
5. **加密**：保格式加密、保序加密、同态加密（可逆，需密钥）。

### 6.3 静态 vs 动态脱敏（DSMM）
- **静态脱敏（SDM）**：上云前批量生成不可逆/可逆副本，用于分析、共享、AI 处理 → 本 SOP 采用。
- **动态脱敏（DDM）**：访问时按权限实时脱敏，用于生产环境权限控制（本场景非必需）。

## 配套一键脱敏本地脚本

技能目录内附带 `scripts/desensitize.py`——一个**本地运行、数据不出本机**的一键脱敏命令行工具，供 AI Agent 在上云前快速执行脱敏。

- **运行环境**：`scripts/` 是一个 **uv 工程**（`pyproject.toml` 声明依赖），由 install.py 创建虚拟环境并安装 `cryptography / python-docx / openpyxl / python-pptx / pypdfium2 / pikepdf / msoffcrypto-tool / rapidocr / onnxruntime / charset-normalizer`；不污染系统或其他项目环境。
- **解释器解析顺序（便携，跨 install / upgrade / 调用 / 测试一致）**：`DESEN_PYTHON`（直接指定解释器，复用现有环境、不新建 venv）→ `DESEN_VENV`（指定 venv 目录）→ `<技能目录>/scripts/.venv`（install.py 默认创建）→ 系统 `python3`。安装时亦可用 `install.py --venv <目录>` / `--python <路径>`（或对应环境变量）显式指定，指定后**绝不自动重建专属 `.venv`**。
- **调用方式**：
  - 默认（离线推荐）：`<技能目录>/scripts/.venv/bin/python <技能目录>/scripts/desensitize.py scan|run <输入> [--out ./desensitized --keys ./.desensitize_keys --mode hybrid|mask|token|redact --recursive --names 姓名清单.txt --cn-enhance]`（WorkBuddy 下 `<技能目录>` 为 `~/.workbuddy/skills/desensitization-sop`）
  - 复用现有环境：`DESEN_PYTHON=/path/to/python <技能目录>/scripts/desensitize.py scan|run <输入> [...]`（或 `DESEN_VENV=/path/to/venv`）
  - 或用 uv：`uv run --project <技能目录>/scripts python …`
- **子命令**：
  - `scan`：仅扫描并报告命中（身份证/手机/银行卡/邮箱/IP/车牌/护照/代码密钥 + 跨境 IBAN/SWIFT/VAT/国际电话，开启 `--cn-enhance` 时含中文姓名/地址/机构名），不生成文件。
  - `run`：输出脱敏副本到 `--out`（默认 `./desensitized`，可上云）；加密映射表到 `--keys`（默认 `./.desensitize_keys`，含 `*.key` 密钥文件，权限 600，**不可与副本同传**）；并生成 `desensitize_report.json` 元数据（命中统计/恢复安全性/碰撞/skip）。
  - `restore`：用 `--keys` 映射表把 `--input`（默认 `./desensitized`）的脱敏副本**回填**为含原值的本地内部文档（`--out` 默认 `./restored`）；支持 `--types` 仅回填指定类型（如 `name,id_card`）。回填产物恢复为实名，仅限本地使用、勿随副本外传；token 模式请勿用于含同名串的数据。
  - `audit`：基于 `run` 生成的 `desensitize_report.json` **自动产出审计文档（九节，对齐 12 项自查清单；九节为清单的多对一汇总，非一一对应）**（`--out` 默认 `./desensitize_audit.md`），覆盖数据盘点/分级/脱敏方法/密钥分离/上云内容/复核结论/skip manifest/风险自评，省去手工填模板。
  - `decrypt`：本地解密映射表供复核（`decrypt --keys ./.desensitize_keys [--out 明细.json]`），无需上云。
- **脱敏模式（默认 `hybrid`）**：`mask`（掩码，可逆）/ `token`（令牌化，可逆且跨记录可关联）/ `hybrid`（语义掩码+唯一令牌，可逆、**无歧义恢复且保留字段语义**，SOP 主线默认）/ `redact`（抑制，不可逆）。
- **生僻字 / 特殊字符（优先 mask）**：待脱敏信息含**生僻字**或**特殊字符**时，脚本**优先全掩码**（`*`），不保留含此类字符的首字/尾字，替换值一律用常见字符（`*`、`[地址]`、`[机构]` 等）——原因：① 生僻字本身是高识别度特征（保留「㐀」作姓氏即泄露）；② 特殊字符（emoji、符号等）可能破坏文本格式或下游处理。
  - **生僻字判定**：CJK 扩展区（Ext-A `U+3400-U+4DBF`、Ext-B~F `U+20000-U+2FA1F`、Ext-G `U+30000-U+323AF`）+ 兼容表意文字（`U+F900-U+FAFF`）——这些字在常用字体/输入法里极少出现，视为生僻字。
  - **特殊字符判定**：非「常见字符」——既非 ASCII 字母数字/常见符号，也非 CJK 基本区汉字、常见中文标点、空白（emoji、控制字符、私有区、数学符号等）。
  - **边界（须人工复核）**：CJK 基本区（`U+4E00-U+9FFF`）内的罕见字（如「爨」「龘」）不在自动判定范围，仍会保留首字——此类高识别度字建议人工复核，或用 `--names` 清单显式处理。
- **`--mapping <文件>`（用户自定义脱敏映射）**：接受用户指定的「原始值→替换值」映射，并**按规则保存**（命中结果随加密映射表 `.desensitize_keys/` 本地加密保存、密钥 600、**绝不外发**；可 `decrypt` 复核、`restore` 回填）。格式：JSON `{"原始值":"替换值", ...}` 或文本每行 `原始值=替换值`（或 TAB 分隔，`#` 注释）。脱敏时**主动精确匹配**原始值并替换为用户指定值（原样、不加令牌），**独立于识别正则**——用户指定即视为需脱敏（无需 `--cn-enhance` 也能替换姓名），且先于 names/正则执行、不会被自动掩码覆盖；未在映射中的值仍按 mode 自动脱敏。⚠ **映射文件本身含敏感信息（原始值），严禁外传、仅本地使用**。
- **`--cn-enhance`（中文识别增强，纯本地离线，无额外依赖）**：额外识别**中文姓名 / 中文地址 / 中文机构名**。
  - 中文姓名：依"姓氏 + 1~2 汉字"，且需带语境（以此抑制中文文本极高误报率，如"中国经济"不会被误识）：
    - **强语境**（标签词 姓名/客户/联系人/经办人/申请人/被谈话人/被询问人/借款人/担保人，或冒号 `:`/`：`）——前缀已提供强上下文，放宽后缀边界（仅按 姓氏+1~2 字 定长），如"客户张三于…"可命中"张三"。
    - **弱语境**（逗号/顿号/空格/括号/句号等**中英文标点**前缀）——保留后缀边界（称谓 先生/女士/… 或**中英文标点**/空格/结尾）。前后边界集 `_CN_BOUND` 同时覆盖全角与半角（`,` `，` `。` `.` `:` `：` `;` `；` `!` `！` `?` `？` `、` `(` `)` `（` `）` 及空白），避免中英文标点混排漏检（如 `客户:张三, 李四.` 中半角句号结尾的"李四"也能命中）。
  - 中文地址：含 省/市/区/县 等行政区划 **或** 路/街/号/栋/室/小区 等楼栋要素（二者至少其一），不强制"行政区划前置"，以覆盖"中关村大街1号"（无市/区）与"北京市海淀区"（无楼栋）等常见写法；中英文标点位于字符类之外，天然作为截断边界，混排不影响。
  - 中文机构：含 公司/集团/银行/医院/大学/研究所/局/协会/分行 等组织后缀。
  - 仍建议人工复核：中文姓名可能漏报（无语境时）或极个别误报（如"赵钱孙先生"会被误识为姓名）；中文机构（如"北京大学"）在示例语境下亦可能被误脱敏——若确为公开主体，请用「显式声明豁免」（§0.5）跳过，而非依赖自动识别。
- **`--tabular-names`（结构化列解析，纯本地离线，零依赖）**：解析 CSV/TSV/xlsx 首行列头，识别「姓名类标签」列（精确匹配 + 排除 phone/address/email 等后缀，避免 `BuyerPhone` 误判），对该列的 Title Case 二词英文姓名（`John Smith` / `Hans Müller`，含拉丁重音）按词保留首字母脱敏（`J*** S****`），**商品名/地址列零误伤**。CSV/TSV 用文本级列头解析、xlsx 用 openpyxl 读单元格结构（规避空格分隔文本列对齐不可靠）。泰文/越南文等非拉丁姓名不在范围，需 `--names`。**NER 模型暂不引入**（需联网下载模型，违背「离线·最小依赖」原则）。
- **可逆性**：mask/token 的原始值仅存于本地加密映射表（AES/Fernet），可用密钥解密还原做本地复核；redact 不可逆。
  - **本地复核命令**：`python desensitize.py decrypt --keys ./.desensitize_keys`（默认解密最新一份映射表并打印摘要；加 `--out 明细.json` 导出 `original↔replacement` 完整明细；若用 `--passphrase` 则同样传同一口令解密）。
- **映射唯一性检测（防止恢复混淆）**：脚本内置 `find_collisions`，自动检查"同一脱敏值 → 多个不同原始值"的多对一歧义，并在 `run` 与 `decrypt` 两处均给出告警；报告 `desensitize_report.json` 含 `restoration_safety`（`unique` / `ambiguous` / `irreversible`）与 `collision_risks` 字段。
  - **`token` 模式：天然 1:1、恢复无歧义**。`token_value` 以"原始值"为键分配唯一令牌（`T0001…`），不同原始值必得不同令牌，每个令牌反向只对应一个原始值，不存在碰撞。
  - **`hybrid` 模式：语义掩码 + 唯一令牌，无歧义且保留字段语义**。替换串 = `掩码外壳 + 分隔符⟦⟧ + 唯一令牌`，例如 `张*`→`张*⟦T0002⟧`、`138****8000`→`138****8000⟦T0001⟧`、`z***@corp.com`→`z***@corp.com⟦T0003⟧`、代码密钥 `***`→`***⟦T0001⟧`。令牌同样以"原始值"为键分配，故：
    - **保留字段语义**：人眼/下游仍能识别"此处原是姓名/手机/邮箱/密钥"；
    - **无歧义恢复**：令牌保证唯一，mask 即使碰撞（如 `zhang@x`/`zhao@x` 同为 `z***@corp.com`）也因令牌不同而可区分；
    - **跨记录关联**：同一原始值处处得同一令牌（如"客户:张三"两次出现均 `张*⟦T0002⟧`），可判断"两处是同一个人"。
    - 分隔符选用极罕见的数学空心方括号 `⟦ ⟧`（U+27E6 / U+27E7），避免与正文混淆。
  - **`mask` 模式：不保证唯一，需看检测结果**。掩码按"类型+格式"推导固定样式，易碰撞：中文姓名（张三/张伟→同为`张*`）、中文地址/机构（全部→`[地址]`/`[机构]`）、同域邮箱（`zhang@x`/`zhao@x`→同为`z***@x`）、同段 IP 等。若 `run` 报告 `restoration_safety=ambiguous`（或 `decrypt` 列出歧义项），则恢复时可能混淆。
  - **`redact` 模式：不可逆**，本就不设计恢复，无歧义问题（也不能还原）。
  - **建议**：凡要求"可无歧义恢复"且又要保留字段语义的场景（即本 SOP 的"可溯源 + 无混淆"主线），**默认即 `--mode hybrid`**（run 子命令默认值已设为 hybrid）；`token` 适用于完全不需要字段语义、只要关系结构的场景；`mask` 仅用于追求纯可读格式、且能接受人工逐条核对映射表的场合。碰撞告警已为 `mask` 兜底——出现 `ambiguous` 时，提示改用 `hybrid` 或 `token` 重新脱敏即可。
- **能力边界**：内置正则，覆盖常见直接标识符（含跨境 IBAN/SWIFT/VAT/国际电话）；**自动化识别非 100% 召回（尤其中文姓名/住址、英文/多语言姓名），脱敏后必须人工复核**，禁止"一键脱敏即上云"。中文用 `--cn-enhance`、表格英文姓名用 `--tabular-names` 做本地增强；**英文/多语言姓名的自由文本（docx 段落/邮件）与泰文/越南文需 NER 模型（需联网下载模型，违背「离线·最小依赖」原则，暂不引入），用 `--names` 名单兜底**。
- **「先清洗再脱敏」清洗建议（小微业务数据随意填写的提醒）**：检测疑似**未清洗数据形态**——带分隔符手机号（`138-0013-8004` / `138 0013 8002`）、10 位手机号、15 位旧身份证、订单号/流水号标签后紧跟 16-19 位纯数字（与银行卡区间重叠易误判）。**只提醒、不自动改**（fail-safe）：scan 控制台逐文件输出 `⚠清洗建议 {类别: 次数}` + 汇总文案；run 报告新增 `cleaning_advice`（分类计数）与 `cleaning_advice_text`。收到提醒请先做字段级数据清洗（去空格/横线、补齐位数、区分订单号与银行卡）或人工复核，再脱敏。
- **已修复的抽取盲区（电商/办公文档实测驱动）**：
  - **docx 表格**：段落之外同时抽取表格（Word 登记表/台账内的身份证、税号、金额不再漏检）；
  - **xlsx 批注**：非只读模式读取批注文本（客服写在批注里的手机号等不再漏检）；
  - **多编码探测**：`BOM → UTF-8 → charset_normalizer → GB18030 → cp1252` 自动探测，覆盖 GBK/GB2312、cp932(Shift-JIS)、big5、cp1252（电商 GBK 报表、日文/繁体/拉丁重音不再乱码，数字/金额脱敏不受影响）；
  - **JWT**：新增 `jwt` 类别（`eyJ` 三段式，所有文本生效，掩码保留 `eyJ` 前缀与末 6 位）；
  - **HTML 内嵌密钥**：html/htm 纳入 `SECRET_PATTERN` 密钥检测（`<script>var adminToken=...` 不再漏检）；
  - **SQL INSERT 位置参数口令**：按「列名含口令关键词 → VALUES 对应位置值」定位脱敏。
- **跨境识别能力（v2.8 新增，跨境电商实测驱动）**：
  - **IBAN / SWIFT / VAT**：`iban`（MOD-97 校验）、`swift`（ISO 国家码校验）、`vat`（欧盟/EEA 国家码限定）——欧盟跨境收付/合同的银行账号/税号不再明文留存；订单号 `SG123456789`、变量名 `CALLBACK` 等被国家码/下划线边界校验过滤，误报可控。
  - **国际电话**：`intl_phone`（`+` 国家码 + 号码组，`+1/+44/+65/+66` 等）自动识别脱敏。
  - **全角归一**：文本预处理把全角数字/字母/空格归一为半角（fullwidth→halfwidth），全角手机/身份证/银行卡正常识别。
  - **csv/json 内嵌密钥**：`SECRET_PATTERN` 扩展至 csv/json（GA token、Stripe api_key 等不再明文留存）。
  - **结构化列解析 `--tabular-names`（v2.9 起，v2.10 扩展 xlsx）**：解析 CSV/TSV/xlsx 列头，识别姓名列，脱敏 Title Case 二词英文姓名（`J*** S****`），商品名/地址零误伤。
- **仍存在的边界（须人工复核/清洗）**：① 无列名 `INSERT INTO t VALUES(...)` 无法定位口令列；② 16-19 位纯数字订单号/计划ID 与银行卡区间重叠会被误判（建议字段级排除或人工确认）；③ `--cn-enhance` 中文机构/地址过匹配（干净报表可能误掩，需人工甄别或显式声明豁免）；④ 15 位旧身份证与分隔/短位手机**不自动改**（仅清洗建议提醒，避免与数字订单号等误伤）；⑤ 英文/多语言姓名：表格 CSV/TSV/xlsx 用 `--tabular-names` 识别；自由文本（docx/邮件）英文姓名与泰文/越南文等多语言姓名需 NER 模型（**暂不引入**，离线原则）或 `--names` 名单召回。

## §7 应急、改进与附录

### 7.1 应急与持续改进
- **泄露应急**：若脱敏副本或映射表意外外泄，立即按数据级别启动预案（隔离、告知、上报），并将事件记入审计。
- **定期重评估**（GB/T 37964 监控审查）：当数据用途、接收方、可获取的外部数据变化时，重新评估重标识风险；定期复核脱敏规则有效性。
- **工具与规则更新**：跟踪 TC260、人行、财政部新标准；更新识别规则与脱敏方法库。
- **人员责任**：明确"谁授权、谁脱敏、谁上云、谁复核"；越权上传原始敏感文件视为违规。

### 7.2 附录 A：直接标识符速查（GB/T 42460 附录A 摘选）
姓名、身份证号、护照号、驾驶证号、详细住址、电子邮件、电话/手机（含国际电话）、传真、银行卡号（含国际银行账号 IBAN / SWIFT/BIC）、车牌/车架号、税号（VAT 等）、社保号、健康卡号、病历号、设备标识、生物识别码（指纹/声纹）、人脸及可比图像、IP 地址、URL 等。

### 7.3 附录 B：敏感个人信息类别（GB/T 45574-2025）
生物识别、宗教信仰、特定身份、医疗健康、**金融账户**、行踪轨迹、不满十四周岁未成年人信息，及其他一旦泄露易致人格尊严受损或人身财产危害的信息。
